## 速度不是越高越好

并发的目标是稳定完成，不是把 CPU 跑满。浏览器 provider 会把 Solve 限制为单个物理并发；这通常是整条流水线的自然上限。

## 各段的默认约束

- P worker 最多 4 个，待收码邮箱也有限制
- C 默认 2 个，避免注册端和邮箱端同时被压垮
- OAuth 默认 2 个，并按 `OAUTH_MIN_INTERVAL_SEC` 限速

吞吐变慢时，先判断瓶颈在打码、邮箱还是服务端限流。盲目增加 P/C worker 往往只会积压更多半成品。
